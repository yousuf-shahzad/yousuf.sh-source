# yousuf.sh

The source for [yousuf.sh](https://yousuf.sh): a React, Vite and Tailwind portfolio.

## Requirements

Use Node.js 20 LTS (or a newer compatible LTS release) and npm.

```sh
npm install
npm run dev
```

`npm run dev` starts Vite and watches project and blog Markdown. Use `npm run build` for a production build; it validates and generates content before Vite runs. The useful quality commands are `npm run lint` and `npm run format:check`.

## Project case studies

Project catalogue entries live in `src/data/projects/*.md`. Each file has frontmatter for the card and, once published, a Markdown case study. Drafts remain visible in the catalogue but cannot expose a case-study link or prose.

To add a sixth project, add one Markdown file with a unique lowercase kebab-case `slug`, title, summary, technology list, links, `caseStudyStatus`, and `relatedProjects`. For a `published` study, supply `role`, `updatedAt`, and meaningful Markdown sections named:

- Problem
- My contribution
- Solution
- Decisions and trade-offs
- Validation and outcomes
- What I learned

`npm run content` reports the filename and field for invalid frontmatter, duplicate slugs, bad URLs, missing related projects, and incomplete published studies. See [the writing guide](docs/project-writing-guide.md) before publishing a study.

Published studies use `/projects/:slug`. The host must rewrite that route to `index.html` for direct requests; configure that behaviour in the selected hosting platform. Add site-map entries only when a study is published.

## Blog posts

Blog posts live in `src/data/blogs/*.md`. Each post has frontmatter for its URL, title, date, tags, publishing state, and optional excerpt. Set `published: false` for a draft: the content command validates it, but the post is not included in the site. Set `published: true` only when it is ready to share.

`npm run content` checks required metadata, duplicate slugs, valid dates, non-empty tags, publishing state, and published post bodies. It also creates excerpts and reading times when they are omitted. See [the blog writing guide](docs/blog-writing-guide.md) before publishing a post.

## Notes

`src/generated/projects.json` and `src/generated/blogs.json` are generated by the content command. Do not edit them by hand. Project screenshots and cover images belong under `public/projects/<slug>/`. A cover image uses `coverImage`, `coverImageAlt`, `coverImageWidth`, and `coverImageHeight` frontmatter; it appears on the project card and, for published studies, at the top of the detail page. Blog images belong under `public/blog/<slug>/` and follow the same accessibility guidance.
